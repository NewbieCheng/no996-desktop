# 01 · 整体认知与上手指南

> 目标：10 分钟内建立正确心智模型，知道「该改哪一层、不该改哪一层」。

---

## 1. 我们在做什么

**不加班智能体** = 桌面工作台(Shell)+ DeepSeek Harness 内核(DSH)+ Go 云端后端。

```text
用户看到的产品          = Shell（侧边栏 + 业务页面 + 品牌）
Agent / Skill / 模型   = DSH Kernel（不重写）
账号 / 积分 / Key 租约 = Go 后端（已有 V1）
```

用户首次旅程（V1 已确认）：**安装 exe → 加载动画（模块与预加载进度）→ 「点击进入」→ 登录页 → 工作台首页（面板模式）**。顶部导航提供两种工作模式切换，见 §3.2。

---

## 2. 三种「插件」，别混为一谈

| 类型 | 放哪 | 谁开发 | 例子 |
|------|------|--------|------|
| **Workbench Module** | Shell 侧边栏 + React 页面 | 前端 / 业务开发者 | 选题池、内容创作页 |
| **DSH Host 插件** | Node 子进程 Cordis | Agent / 平台工程师 | credentials lease、billing |
| **DSH Skill** | 用户目录 `SKILL.md` | 用户 / 运营 | 自定义专家 Prompt |

**误区**：把整页业务 UI 写进 DSH Client 插件。DSH Client 是为 **Agent 对话 UI** 设计的，不适合全屏工作台。

**正确**：业务页 = Module；需要 AI 时调 `shell.agent.run()`；重计算（如 ffmpeg 媒体处理，V2）= DSH Host tool。

## 3. 窗口布局（已确认）

```text
┌─────────────────────┐     ┌─────────────────────┐
│  Window A: Shell    │     │  Window B: Agent    │
│  · Sidebar          │     │  · DSH Web UI       │
│  · Module 主区域    │────►│  · Skills           │
│  · 12 业务页        │ IPC │  · Workspace        │
└─────────────────────┘     └─────────────────────┘
         │                            │
         └────────── Main Process ────┘
                    · 密钥 · 验签 · DSH 子进程
```

两窗口通过 **Main Process IPC** 协作；Module 不直接加载 DSH 页面。

### 3.1 Shell 启动链（已确认）

```text
启动 exe
  → 加载窗口：品牌 Logo + 模块加载 / 预加载进度动画
  → 加载完成 → 「点击进入」按钮点亮
  → 登录页（手机号 / 验证码，走 Go 后端 /auth）
  → 登录成功 → 进入工作台首页（默认面板模式）
```

### 3.2 顶部导航：双模式（已确认）

| 模式 | 内容 | V1 交付形态 |
|------|------|-------------|
| **工作台面板模式** | 左侧 Sidebar + 业务 Module 页，即交付包 12 页 + 设置页的完整形态 | 完整实现，UI 用 web/admin 的 shadcn/ui 体系重组 |
| **智能工作台模式** | 顶栏切到 Agent 面板视角：按左侧功能模块逐页执行 AI 操作（选题→创作→排期→复盘的连贯工作流） | V1 先落架构与页面骨架：Agent 窗口 + 顶栏切换 + 可见即可点的页面框架；不必全部跑通业务闭环 |

两个模式共享同一份 Module Registry 与登录态；切换只改主区域视图，不重开进程。

### 3.3 首页形态（已确认）

首页 = AI 聊天入口 + 工作台概况：顶部是「今天该干什么」的 AI 对话框，AI 返回引导动作，点击跳转左侧对应功能页（`shell.nav.go()`）；下方保留交付包首页的简报卡片区。

## 7. 第三方：上手一个 Module

```bash
# 1. 从模板创建（待提供 module-starter）
pnpm create @no996/module my-feature

# 2. 编辑 manifest
#    modules/my-feature/module.manifest.json

# 3. 写页面
#    modules/my-feature/src/pages/MyPage.tsx

# 4. 本地调试
pnpm --filter @no996/shell dev

# 5. 打包安装
pnpm --filter @no996/my-feature pack
# → 拖入 Shell 设置页，或解压到 AppData/No996/modules/
```

### 最小 Module 代码

```typescript
// modules/my-feature/src/index.ts
import type { No996Module } from '@no996/module-sdk';
import { MyPage } from './pages/MyPage';

export const MyFeatureModule: No996Module = {
  id: 'my-feature',
  routes: [{ pattern: '#my-feature', activeNav: 'my-feature' }],
  Page: MyPage,
};
```

```typescript
// modules/my-feature/src/pages/MyPage.tsx
import type { ModulePageProps } from '@no996/module-sdk';

export function MyPage({ shell }: ModulePageProps) {
  const runAi = async () => {
    await shell.agent.open({ preset: 'my-preset' });
    const result = await shell.agent.run({
      taskId: crypto.randomUUID(),
      input: { text: 'hello' },
    });
    console.log(result.output);
  };

  return (
    <div>
      <h1>我的功能</h1>
      <button onClick={runAi}>调用 Agent</button>
    </div>
  );
}
```

## 10. 常见问题（认知层）

**Q：DSH 升级会不会弄坏业务 Module？**  
A：Module 只依赖 `No996Shell` Bridge semver，不 import DSH 源码。DSH bump 后跑 Bridge 契约测试即可。

**Q：用户自装 Skill 放哪？**  
A：`~/.no996/skills/`，DSH `skill-filesystem` 扫描。**设置页提供 Skill 管理面板**（列出/启用/停用/查看详情），Shell 不重写发现逻辑。

**Q：新页面一定要走后端审批吗？**  
A：本地安装可 dev 自用；OTA 上架需签名 + 租户白名单（企业管控）。

**Q：智能工作台模式 V1 要做到什么程度？**  
A：V1 交付「架构框图级」实现：顶栏切换、Agent 窗口可打开、能看到各功能页的执行入口；不要求每个业务闭环都真正跑通 AI 流程，扣费/积分相关界面先做展示位（余额、解锁按钮），真实扣费链路随 P1 Bridge 落地。
